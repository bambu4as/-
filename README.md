# Pocket Option бот: сигналы CALL/PUT

Схема решения: **данные → Analyzer → XGBoost + Random Forest (или LLM) → CALL/PUT**.
Арбитра нет. Если модель не уверена, сделка пропускается (NONE).

## Структура

| Путь | Что внутри |
|---|---|
| `server.js` | Express-сервер, `/api/signal`: свечи → анализ → решение модели → журнал |
| `po-socket.js` | WebSocket-клиент Pocket Option: свечи, подписки, история (`loadHistoryPeriod`) |
| `candles.js`, `analyzer.js` | нормализация свечей и анализ (индикаторы, экспирация) |
| `llmCore.js` | клиент сервисов решения, выбор адреса по сегменту и периоду |
| `timeframes.js` | таймфреймы (внутри в секундах: 5, 15, 30, 60, 180, 300) |
| `journal.js`, `tracker.js` | журнал решений и исходов, статистика win rate |
| `bot.js` | Telegram-бот (отдельный процесс) |
| `public/` | веб-приложение (выбор пары, таймфрейма, сигнал) |
| `config/` | `segments.json` (сегменты, периоды, признаки), `history.json` (загрузка истории) |
| `llm/` | сервис LLM (GGUF через GPT4All), альтернатива деревьям |
| `ml/` | деревья: признаки, обучение, оценка, одобрение, HTTP-сервис |
| `train/` | датасеты (`build_dataset.py`), базовые линии (`evaluate.py`), LoRA |
| `tools/` | загрузка истории, сбор свечей, проверка файлов, статистика |
| `tests/` | тесты Node |
| `data/`, `train/data/`, `train/out/` | данные и модели (не в git, см. `.gitignore`) |

## Сегменты

Определяются по имени пары: в имени есть `OTC` → `otc`, иначе `currency`. Выходные на сегмент не влияют.
Данные, модели и одобрения у каждого сегмента свои.

## Порядок работы

1. **Проверка кода:** `npm run test:all` (синтаксис, Node-тесты, Python-тесты).
2. **История:** `node tools/history_download.js --list`, затем `--pair N` по одной паре.
   Формат запроса подтверждён: `loadHistoryPeriod` с `offset` 9000 с.
3. **Датасет:** `python3 train/build_dataset.py <csv> --pair "..." --segment otc --period 60`.
4. **Обучение и одобрение:** см. `ml/README.md`. Сегмент без одобрения не торгует.
5. **Сервисы:** по одному на сегмент и период. Адреса в `.env` (`LLM_URL_<СЕГМЕНТ>_<СЕК>`).
6. **Бот:** `node server.js`, открыть веб-приложение.

## Безопасность

- Модель торгует сегмент только после одобрения на тесте (`APPROVED.json`, привязан к хешу модели).
- Сервис отказывает запросам другого сегмента и другого периода (409).
- Тест используется один раз, повторные проверки журналируются.
- Секреты только в `.env` (шаблон: `.env.example`), в git не попадают.

## Известные ограничения

- Признаки моделей: 20 доходностей. Индикаторы аналитики в обучении не участвуют.
- Горизонт метки — следующий бар. Для экспирации, отличной от периода, нужна правка `build_dataset.py`.
- Доступность периодов 5, 15, 30 с у брокера подтверждается только пробой.
