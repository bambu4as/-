# Схема: Данные → Analyzer → XGBoost + Random Forest → CALL/PUT

Арбитра нет. Направление даёт среднее P(CALL) двух моделей. Если модель не уверена
(|P − 0.5| меньше порога), бот пропускает сделку (NONE). Порог выбирается на валидации.

## Что сделано в коде

| Файл | Назначение |
|---|---|
| `ml/features.py` | признаки (20 доходностей, версия `returns20-v1`) и решение с воздержанием |
| `ml/models.py` | Random Forest и XGBoost, среднее вероятностей |
| `ml/train_trees.py` | обучение на train, выбор порога на val, тест не трогается |
| `ml/evaluate_trees.py` | оценка на тесте, журнал проверок, одобрение `APPROVED.json` |
| `ml/tree_server.py` | HTTP-сервис `/decide`, тот же контракт, что у LLM; работает только для одобренного сегмента |
| `ml/test_ml.py` | 12 тестов: признаки, решение, порог, защита одобрения, HTTP |

## Защита от торговли без проверки

Сервис отказывает в решениях (503), пока:
- нет `train/out/<сегмент>/trees/APPROVED.json`;
- хеш `bundle.joblib` не совпадает с хешем из одобрения (подмена модели);
- запрос пришёл с другого сегмента (409).

Одобрение выдаёт только `evaluate_trees.py --approve` и только если критерий пройден на тесте.

## Порядок работы по сегменту

Нужны данные из `train/build_dataset.py` (см. `train/README.md`, шаги 1–2).

```
pip install xgboost                                  # один раз
python3 ml/train_trees.py --segment otc              # обучение, порог по val
python3 ml/evaluate_trees.py --segment otc           # тест, один раз: отчёт
python3 ml/evaluate_trees.py --segment otc --approve # только если критерий ПРОЙДЕН
ML_SEGMENT=otc LLM_PORT=8788 python3 ml/tree_server.py
```

В `.env` для этого сегмента: `LLM_URL_OTC=http://127.0.0.1:8788/decide`.
Сегмент без одобрения не торгует: сервис отвечает 503, бот пишет NONE.

## Что ещё не сделано и почему

- Признаки только доходности. Аналитика (`analyzer.js`) в обучении не участвует:
  её индикаторы считаются в JavaScript, а обучение в Python. Чтобы добавить их,
  нужна та же формула в Python, и проверка совпадения, как для доходностей.
- Горизонт метки — следующий бар. Для 5-секундных сделок с экспирацией в минуту
  метку нужно перевести на горизонт экспирации (12 баров). Это отдельное изменение `build_dataset.py`.
- Тест используется один раз. Повторные проверки на тесте журналируются и помечаются как сомнительные.

## Числовой путь (для больших датасетов)

`ml/prepare.py` строит массивы напрямую из CSV без JSON-промптов. Проверено тестом: те же времена,
метки и признаки, что у `train/build_dataset.py`.

```
python3 ml/prepare.py --csv-dir /path/to/otc --segment otc --out train/data/otc/arrays
python3 ml/baselines.py --arrays train/data/otc/arrays/merged.npz --split val
```

`ml/baselines.py` показывает базовые линии и безубыточность. Тест используется только командой с `--split test`.

Режимы решения: с воздержанием (по умолчанию, ничья → NONE) и «только CALL/PUT» (порог 0, ничья → CALL).
Режим «только CALL/PUT» без подтверждённого сигнала даёт убыток при выплате 80%.


## Наборы признаков (обучение и работа должны совпадать)

| Набор | Что в запросе | Где задаётся |
|---|---|---|
| `returns20` | 20 доходностей, б.п. | по умолчанию |
| `returns20+ind_main8` | 20 доходностей + 8 индикаторов | `LLM_FEATURE_SET`, `ML_FEATURE_SET` |

- Node (`llmCore.js`) присылает `feature_set` и, для набора с индикаторами, 8 значений из `ml_indicators.js`
  без округления. Индикаторы считаются по последним 300 закрытым барам.
- Python (`ml/indicators.py`) считает те же формулы по полной истории. Совпадение проверяет тест по
  `tests/fixtures/ind_parity.json` (сгенерирован `tools/gen_ind_fixture.js`).
- Сервис деревьев отказывает в решении (409), если набор запроса не совпадает с `ML_FEATURE_SET`,
  и (503), если бандл обучен на другом наборе. LLM-сервис принимает только `returns20`.
- Обучение по массивам: `ml/prepare.py` (сохраняет X и I), затем
  `ml/train_arrays.py --feature-set returns20+ind_main8`.
